# Корректирующий план аудита Terricon Events Bot v1

Статус: завершён 2026-09-20.

План не расширяет scope v1 и закрывает расхождения, найденные при постреализационном
сопоставлении кода со спецификацией и основным планом.

## 1. Пользовательские и административные сценарии

- Показывать в preview feedback те же имя и `@username`, которые получит администратор.
- Локализовать доставляемые пользователю ответ администратора и сообщение о закрытии тикета.
- Показывать в `/status` состояние каждого Terricon endpoint, а не только число ошибок.
- В итоговом отчёте рассылки учитывать получателей, для которых потребовался transient retry.
- Зарегистрировать отдельный scheduler job выпуска накопленного ночного дайджеста после 09:00.

## 2. Наблюдаемость

- Материализовать дедуплицированные admin-alerts для 24-часового GPT fallback и длительных
  либо окончательных ошибок outbox/broadcast.
- При повторяющейся недоступности PostgreSQL отправлять сгруппированный runtime-alert напрямую,
  поскольку сохранить его в недоступной БД невозможно.
- Не включать в alert/log пользовательские ID, тексты сообщений или секреты.

## 3. Проверка

- После каждого блока запустить его unit/integration tests.
- Затем выполнить Ruff, format check, mypy, полный PostgreSQL test suite, проверку lock-файла,
  shell-скриптов и Docker Compose healthcheck.

## 4. Результат

- Все перечисленные расхождения устранены без расширения scope v1.
- Добавлены общие raster-assets главного меню и всех девяти категорий; отсутствие
  локализованных переопределений по-прежнему штатно обрабатывается fallback-цепочкой.
- Итоговый PostgreSQL gate после hardening-аудита: `209 passed`.
- Ruff, Ruff format, mypy, lock check, shell syntax и `git diff --check`: пройдены.
- Docker image build, Compose config, migrations, container preflight и healthcheck: пройдены.
- Реальный backup/restore smoke: revision `0010_hardening_queue_state`, 25 public-таблиц.
- Read-only live Terricon smoke: все шесть endpoint ответили успешно.
