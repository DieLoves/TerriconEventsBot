# Hardening импорта Terricon API после аудита

Статус: завершён 2026-09-18.

## Цель

Устранить дефекты этапа 3, не меняя продуктовый scope и схему PostgreSQL:

- не считать endpoint успешным, если непустой ответ целиком состоит из невалидных записей;
- не завершать baseline, не скрывать события и не пропускать smoke при таком ответе;
- не загружать и не обновлять уже скрытый архив на каждом цикле;
- сохранять переносы строк в описаниях;
- закрывать source mismatch/collision alerts после подтверждённого полного восстановления;
- ограничить `Retry-After` и размер HTTP-ответа;
- ужесточить проверку внешних HTTP(S)-URL;
- сохранять запись о начатом sync run отдельно от транзакции импорта и отмечать её failed,
  если транзакция БД откатилась.

## Реализация

1. Усилить `TerriconClient`: bounded streaming response, capped retry delay и ошибка
   `all_records_invalid` для непустого полностью отбракованного payload.
2. Разделить очистку однострочных и многострочных полей; для URL запретить credentials,
   пробелы/control characters, непубличные IP/hostnames и некорректные DNS labels.
3. В `SyncService` вынести создание `sync_runs` в короткую audit-транзакцию, а основной
   merge оставить атомарным; при rollback обновлять audit row отдельной транзакцией.
4. Ограничить выборку missing-кандидатов доступными событиями, сохранив точечную загрузку
   наблюдаемых/восстанавливаемых source ID.
5. На полностью успешном цикле закрывать больше не воспроизводящиеся source alerts.
6. Добавить regression-тесты для каждого дефекта, затем прогнать unit/integration gate,
   Ruff, formatter, mypy и проверки diff/lock.

## Критерии готовности

- Полностью невалидный непустой payload даёт endpoint failure во всех путях.
- Пустой валидный список по-прежнему участвует в двухцикловом missing detection.
- Скрытые события не выбираются массово и не получают UPDATE на обычном полном цикле.
- Повторный согласованный полный ответ закрывает mismatch/collision alert.
- При ошибке основной DB-транзакции остаётся `sync_runs.status=failed` с безопасным кодом.
- Все существующие и новые проверки проходят.

## Результат

Все пункты реализованы без изменения схемы БД. Полный gate на PostgreSQL 17 завершился
результатом `89 passed`; Ruff, formatter, mypy, `git diff --check` и offline lock check
прошли. Read-only live smoke принял 406/406 записей шести endpoint с первой попытки.
