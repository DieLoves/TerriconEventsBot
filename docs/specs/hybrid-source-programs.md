# Гибридный источник событий и программы Terricon Valley

Статус: реализовано и выкачено 2026-10-26 (`b4102d9`, вариант C).
Дополняет [`terricon-events-bot.md`](terricon-events-bot.md), разделы 2, 3 и 5.
Если правило здесь противоречит основной спецификации, действует этот документ.

## 1. Зачем

`getAllEvents` по трём темам отдаёт только лекции, митапы и обучение со статусами
`new_mitap`/`end_mitap`. Неконференции, хакатоны, акселераторы, инкубаторы и курсы
живут в `eventsByStage`; поэтому бот не видит, например, неконференцию 30.10.

## 2. Проверено вживую 2026-10-26

`GET https://server.terricon.kz/terra/api/eventsByStage?lang=ru|kz` (без `_=`):

- HTTP 200, ~400 КБ на язык; объект `{"eventsNew": [...], "eventsPreparation": [...]}`,
  74 + 216 = 290 записей, `id` уникальны, RU/KZ — одни и те же `id` и даты.
- Обе группы содержат и прошедшие, и будущие записи (`eventsNew` — 2024-09…2026-10-30,
  `eventsPreparation` — 2024-07…2026-10-23). Группа не означает актуальность.
- Все 209 событий `getAllEvents` (6 запросов) присутствуют с теми же `id` и
  побайтно теми же полями. Новых записей 81, у всех `status=unknown_status`.

Отличия от исходного описания задачи:

- `type=default` только у 31 новой записи (неконференции, конференции, 1 курс).
  Остальные 50 имеют `type=it|business|marketing` и новые `eventType`: `hackaton`,
  `accelerator`, `incubator`, `OC`, `course`, `umitup`, `workshop`. Признак «нового
  вида» — `eventType`/статус, а не `type`.
- У 34 новых записей **нет поля `type_text`** — текущий DTO отбросил бы их как
  невалидные.
- Заглушки встречаются не только в ссылках: `address="-"`, `to_whom="-"`,
  `contact="- -"`, `description="-"`, `language=["-"]`; в `url_live`/`complete_url` —
  `-` и `/`.
- `url_live` неконференций — `https://terricon.kz/neconf-links`: это страница
  после успешной отправки формы (`data-success-url`), а не регистрация.
- `uid` новых записей вида `-30.10` и на страницах программ не обрабатывается.
  Зато 41 из 44 страниц программ (`/ru/neconf`, `/ru/hackathon`, `/ru/accelerator`,
  курсы, KZ-версии) содержит Tilda-якорь `<a name="form">` прямо перед блоком
  формы заявки: `<страница>#form` прокручивает к форме средствами браузера.
  Исключения: `/ru/incubator` и `/ru/it-ai` отвечают 404, у `ethics-by-design`
  якоря нет; две записи ведут на внешние сайты (`forms.gle`, `codetalks.kz`).
- `eventType` неточен: `umitup` («Уникальный митап») включает и бесплатные курсы,
  `workshop` — это IT/Hub Conference.

## 3. Гибридная синхронизация

Цикл (по-прежнему раз в 6 часов, ручной и стартовый — так же):

1. Основной источник: `eventsByStage` для RU и KZ (2 запроса, те же таймаут, повторы,
   `Retry-After`, лимит тела). Записи обеих групп объединяются.
2. Если оба запроса успешны — цикл `source=stage`, полный успех.
3. Если хотя бы один запрос `eventsByStage` исчерпал попытки — в том же цикле
   выполняется прежний опрос `getAllEvents` (6 запросов), цикл `source=legacy`
   с прежней логикой частичного успеха. Данные удачного языка `eventsByStage`
   в таком цикле не используются.
4. URL: `STAGE_URL` (необязательный), по умолчанию — соседний путь `BASE_URL`
   (`…/api/getAllEvents` → `…/api/eventsByStage`). Изменение production `.env`
   не требуется.

Пропадание:

- В цикле `stage` с полным успехом отсутствие считается для всех доступных событий
  (источник содержит всё); скрытие и уведомление «отменено» — после двух
  последовательных таких циклов, как раньше.
- В цикле `legacy` **счётчик отсутствия не растёт ни у одного события**; встреченные
  события обновляются и сбрасывают счётчик. Отмены во время отката не
  обнаруживаются — это осознанная цена: резерв не видит программы и не должен
  принимать их за отменённые.
- Смена источника между циклами не создаёт изменений: общие поля 209 событий
  совпадают в обоих источниках.

Наблюдаемость:

- `sync_runs` хранит источник цикла; состояние endpoint ведётся отдельно для
  `stage:ru`, `stage:kz` и шести `legacy` endpoint.
- `/status` админа показывает текущий источник и, при откате, с какого момента он
  длится.
- Сбой `eventsByStage` при работающем резерве не шлёт alert сразу. Если откат
  длится не меньше `SOURCE_FALLBACK_ALERT_HOURS` (по умолчанию 24 ч), админ получает
  один дедуплицированный alert `sync_source_fallback`; он закрывается первым
  успешным циклом `stage`. Сбои самого резерва alert-ятся как раньше.
- `terricon-api-smoke` проверяет и `eventsByStage` (оба языка), и шесть `getAllEvents`.

## 4. Нормализация

- `type_text` необязателен; лишние/отсутствующие косметические поля не делают
  запись невалидной.
- `eventType` сохраняется в событии как есть в нижнем регистре (`event_type`).
  Вид для показа выводится в коде:
  `neconf` → неконференция, `hackaton` → хакатон, `accelerator` → акселератор,
  `incubator` → инкубатор, `course`/`oc` → курс; остальные (`lecture`, `edu`,
  `mitup`, `umitup`, `workshop`, неизвестные) → обычное мероприятие.
- Тема (`source_theme`) для `type=default` (и любого неизвестного `type`) — первый
  тег из `leads_info.tags` в порядке `it`, `business`, `marketing`, иначе `it`.
  Без предупреждения `theme_mismatch`. Для `eventsByStage` ожидаемой темы нет:
  тема берётся из записи.
- Заглушки: строка, которая после очистки равна `-`, `/` или `- -`, считается
  отсутствующей — в ссылках, адресе, аудитории, описании, спикере и языках.
  Заглушка ссылки не порождает предупреждения `invalid_url`.
- Статус `unknown_status` — штатный, без предупреждения: актуальность и кнопки
  определяются датой (до конца дня проведения по `Asia/Almaty`, как в каталоге);
  выбор кнопки делает карточка.
- Ссылка на сайт (`details_url`, по локали):
  - страница темы (`/ru|kz/it|business|marketing`) → `#<uid>` (как сейчас);
  - другая страница `terricon.kz` → `#form`;
  - внешний сайт → как есть.
- Для `unknown_status`: `registration_url` — страница заявки без учёта локали
  (RU-страница с `#form`: KZ-запись приводит `/kz/…` к `/ru/…`, чтобы общее поле
  RU/KZ совпадало; внешний сайт — как есть), `recording_url` —
  ссылка действия (`url_live` или `complete_url`, если не заглушка). Карточка и
  дайджест, как и сейчас, предпочитают локализованный `details_url` с якорем,
  поэтому KZ-пользователь попадает на `/kz/…#form`. «Регистрация» — до конца дня
  проведения, после — «Запись»/«Подробнее» по прежним правилам. `…-links` и стримы
  не выдаются за регистрацию.
- Записи с известными статусами обрабатываются как раньше.

## 5. Показ программ (решение пользователя 2026-10-26: вариант C)

Из трёх предложенных вариантов (A — отдельный раздел для всех видов, B — всё в общем
каталоге, C — смешанный) выбран C.

Две группы:

- **Мероприятия с видом**: неконференции и хакатоны (однодневные события).
  Показываются в общем каталоге «Мероприятия» вместе с лекциями и митапами,
  классифицируются GPT, рассылаются подписчикам категорий и «Все» по обычным
  правилам. В списке и карточке — бейдж вида («🎤 Неконференция», «🏆 Хакатон»).
- **Программы**: акселераторы, инкубаторы, курсы (наборы на недели). В общий
  каталог не попадают. Новый пункт главного меню «🚀 Программы»: список с
  переключателем вида «Все / Акселераторы / Инкубаторы / Курсы» и
  «Актуальные / Архив» (без периода, категорий, формата и языка). Состояние
  раздела запоминается отдельно от фильтров «Мероприятий»; переход между
  разделами не сбрасывает фильтры другого раздела.

Подписка на программы — отдельный переключатель «🚀 Новые наборы в программы» на
экране «Подписки», по умолчанию выключен и не зависит от категорий и «Все».
Уведомления о новых программах и их важных изменениях/отменах получают только
пользователи с включённым переключателем; подписчики категорий и «Все» их не
получают. Программы тоже проходят GPT-классификацию (одна очередь и задержка
`NEW_EVENT`), но их категории не используются для отбора получателей.

Карточка:

- строка «Вид»; для программ дата подписана «Старт»;
- для записей нового вида (не лекция/митап/обучение) не выводятся пустые адрес,
  язык и категории (у программ категорий в UI нет);
- кнопка до конца дня старта: «📝 Подать заявку» для программ, «📝 Регистрация»
  для мероприятий (обе ведут на `страница#form` или внешний сайт); после —
  прежние «Запись»/«Подробнее».

Дайджест: перед названием записи нового вида ставится бейдж вида.

## 6. Уведомления при включении

- Первый цикл `stage` после выкатки — обычный (baseline уже пройден): новые события
  классифицируются и могут попасть в дайджест.
- Новое событие, день проведения которого уже прошёл (`Asia/Almaty`), не получает
  ожидание `NEW_EVENT` вовсе. Прошедшие программы не рассылаются и не создают
  domain changes; ~80 исторических записей молча попадают в архив.
- Будущие записи (сейчас — неконференция 30.10) рассылаются по правилам раздела 5.
- Переход источников (`stage`↔`legacy`) сам по себе не создаёт уведомлений.

## 7. Приёмка

- Unit: DTO без `type_text`, заглушки, тема для `default`, `event_type`, ссылки
  `#uid`/`#form`/внешние, `unknown_status`, разбор `eventsByStage` и ошибки формы
  ответа.
- Integration (PostgreSQL 17): `stage` полный успех и скрытие после двух циклов;
  откат на `legacy` не увеличивает счётчик и не создаёт отмен для программ;
  возврат к `stage`; частичный сбой резерва; alert отката по порогу и его
  закрытие; первый цикл с прошедшими и будущими программами — domain change только
  для будущих; миграция upgrade/downgrade.
- Живые: `terricon-api-smoke` по 8 endpoint; после выкатки sync `stage`, ~290
  событий, 0 domain changes по прошедшим.
