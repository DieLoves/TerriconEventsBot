# Переход Terricon Events Bot на Groq

Принято пользователем 2026-10-21: полностью заменить зависимость `openai` официальным
SDK `groq`. Дополнение к `terricon-events-bot.md`; этапы 1–8 остаются историей реализации.

## Требования

- Единственный AI-провайдер — Groq; модель по умолчанию `openai/gpt-oss-120b`.
  Префикс `openai/` — ID модели в Groq, а не зависимость или обращение к OpenAI API.
- Использовать `AsyncGroq` и Chat Completions с `response_format.type=json_schema`,
  `strict=true`, без streaming/tools. Схемы генерировать из существующих Pydantic DTO;
  после получения JSON повторно проверять бизнес-правила Pydantic.
- Сохранить 1–3 уникальные категории, исключительность `other`, отдельную операцию
  перевода отсутствующей RU/KZ-локали, приоритет официального текста и 24-часовой fallback.
- Использовать только `GROQ_*` AI-настройки, обязательный `GROQ_API_KEY`, timeout 30 с,
  мягкий месячный бюджет $5. На Free учёт стоимости по умолчанию нулевой; токены сохраняются.
- Не использовать скрытые повторы SDK: retry и `Retry-After` принадлежат очереди.
  Ограничение Groq не должно приводить к немедленному повторному внешнему вызову в batch;
  время следующей попытки сохранять в БД, проверку fallback не откладывать за 24 часа.
- Повтор перевода хранить на completed classification через существующий
  `next_attempt_at` с lease, не повторяя классификацию и пользовательские уведомления.
  Отказы перевода повторять не дольше 24 часов после классификации; появление
  официальной локали прекращает повторы.
- Отказы, обрезанный/невалидный JSON, неправильный usage, timeout, connection и HTTP
  ошибки преобразовывать в безопасные коды без текста событий/секретов в логах.
- Публичные Python-типы usage/ошибок/стоимости сделать нейтральными к провайдеру.
  Существующие SQL-имена `openai_usage`, `openai_operation`, индексы и миграции сохранить
  ради совместимости данных; никакой зависимости от старого SDK это не создаёт.
- Не менять пользовательский `.env`, не переносить ключи из других проектов.
  Для запуска потребуется отдельно настроить `GROQ_API_KEY`; старый ключ не подходит.

## Приёмка

Этап 9: SDK, настройки, очередь и документация переведены; локальные тесты с настоящим
SDK и HTTP MockTransport, PostgreSQL-регрессия, Ruff/mypy/lock/build проходят.
Нет зависимости/импортов `openai`. Живые запросы не входят в offline-приёмку.

Этап 10: после настройки аккаунта проверить 20–30 размеченных событий и RU/KZ-переводы,
измерить usage/latency, сверить квоты аккаунта, настроить ограничение RPM/TPM/RPD/TPD
для классификации и перевода вместе. Учесть начальный импорт, рестарт и расход квот
другими приложениями организации. До этой проверки достаточность Free не подтверждена.
